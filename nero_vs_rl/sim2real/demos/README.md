# 示范数据：用 NERO 工程的真机抓取做 RL 示范

NERO 工程（`/home/yunfeiwu/adddisk1/nero_conveyor_ros2-main`）用固定相机 + 开环规划抓取，真机成功率约 95%，动作平滑。
在它抓取的同时录下**腕部 DC1 深度 + 机械臂关节 + 夹爪开口**，再按 RL 自己的观测和动作格式转成示范数据，给 RL 训练用：
- 预训练策略（行为克隆）；
- 或者放进 SAC 的经验池。

分工：

| 部分 | 在哪 | 说明 |
|---|---|---|
| **采集** | NERO 工程：网页实验台勾“录腕部 DC1（RL 数据）”（默认勾选），或命令行 `--record-wrist-dc1` | 只读的单独进程，录到本项目数据盘 `MY_RL_test/real/nero_demos/<运行目录名>/`，结束时把每件的执行日志也复制过来。用法见 NERO 的 `docs/腕部DC1同步录制.md` |
| **转换** | 本目录 `build_demos.py` | 读上面那个目录，`demos.npz` 写在同一个目录里 |

转换要用 RL 自己的观测定义：
- **观测**：用和真机部署完全相同的代码算（`deploy/runtime/episode.py` 的 `LivePerception` + `envs/observation.py` 的 `assemble_obs`）；
- **动作**：从 NERO 发出的 100 Hz 关节指令反推（`actions.py`，是 RL 控制器的逆运算）。

所以转换放在这里；NERO 那边只交“数据”。

```text
MY_RL_test/real/nero_demos/continuous_<时间>_<pid>/      （NERO 实验台启动抓取时自动生成）
  meta.json、frames.jsonl、depth/、joints_hist.npz      腕部 DC1 深度、100 Hz 关节、夹爪开口
  nero_cycles/cycle_NNN/                                每件的 100 Hz 关节指令、阶段、夹爪指令、是否夹住（从 NERO 复制）
  belt_speed.json                                       带速：每件冻结时的 Uno 带速和速度向量、约 1 Hz 的读数
        │
        ▼  build_demos.py
  demos.npz、demos_summary.json                         写在同一个目录
```

## 现场

在 NERO 网页实验台照常“启动机械臂”，保持“录腕部 DC1（RL 数据）”勾选即可（命令行则是加 `--record-wrist-dc1`）。详细说明见 NERO 的 `docs/腕部DC1同步录制.md`。**机械臂会运动，由操作者执行。** DC1 不在 NERO 的碰撞模型里，第一次先单件、低带速确认不会刮碰。不同物体、不同带速最好分开跑，以后好筛选。

## 生成示范数据

```bash
cd /home/yunfeiwu/桌面/my_RL && source .venv/bin/activate
```

```bash
python -m nero_vs_rl.sim2real.demos.build_demos --run /home/yunfeiwu/adddisk1/MY_RL_test/real/nero_demos/continuous_20261126_150002_12345
```

目录名是示例，换成实际的（`ls /home/yunfeiwu/adddisk1/MY_RL_test/real/nero_demos` 可以看到每次运行一个）。如果执行日志没复制过来（比如被强制终止），脚本会按 `meta.json` 里记的运行目录去 NERO 工程读。

**看终端输出的三项检查：**

| 项 | 正常 | 不正常说明什么 |
|---|---|---|
| 实测关节落后指令 | 50～200 ms | 腕部录制和执行日志对不上（不是同一次运行，或者时间有问题） |
| 看得到物体的拍 | 和离线回放差不多（几十 %） | 很低：DC1 没对准带，或者 NERO 等待位上 DC1 看不到来料 |
| 动作被截断的拍 | 约 15%（NERO 转到抓取朝向时，单步旋转超过 RL 的 0.1 rad） | 很高：NERO 的动作 RL 做不到，要放宽 `max_delta_*` 再训练 |

## 输出格式（`demos.npz`）

| 键 | 形状 | 含义 |
|---|---|---|
| `obs_<键>` | (T, …) | RL 观测字典的 7 个键，和 `DynamicGraspEnv.observation_space` 一致 |
| `action` | (T, 7) | 示范动作（已截到 [−1, 1]） |
| `action_raw`、`clipped` | (T, 7)、(T,) | 截断前的动作、这一拍有没有被截断 |
| `episode`、`episode_last` | (T,) | 属于第几个示范回合、是不是该回合最后一拍 |
| `t` | (T,) | 相对 NERO 接近段开始的时间（s）；闭爪约在 1.1 s |
| `visible`、`gripper_width`、`tcp`、`obj_center` | | 这一拍看没看到物体、实测夹爪开口、TCP 位置、检出的物体中心（没检出为 NaN） |
| `obj_vel_est` | (T, 3) | RL 自己的视觉测速（记忆/测速模块的估计，m/s） |
| `episode_cycle`、`episode_success` | (回合数,) | 对应 NERO 的第几件、NERO 是否确认夹住 |
| `episode_belt_speed`、`episode_belt_velocity` | (回合数,)、(回合数, 3) | NERO 冻结这一件时用的 Uno 带速（m/s）和基座系速度向量；没有 `belt_speed.json` 时为 NaN |

带速不进策略的观测（RL 只靠视觉测速），它是标签：
- 按带速筛选、分组数据；
- 核对 RL 的视觉测速准不准。终端会打印“RL 视觉测速比 Uno 偏多少”，`demos_summary.json` 里每个回合都有 `belt_speed_cm_s` 和 `vision_speed_cm_s`。

每个示范回合从窗口里**第一次完整检出物体**开始（和部署时策略启动的条件一样），到 NERO 接近段结束（闭爪、跟随、减速）为止。之后 NERO 的原地保持、搬运入框、返回都不是 RL 的任务，不放进来。

## 2026-11-27 第一次真机数据

NERO 实验台勾着“录腕部 DC1”跑了两组（带速 17.8 cm/s；另有一次 7 s 的启动失败，没有可用数据）：

| 数据目录 | 件数 | 示范回合 / 拍 | NERO 确认夹住 | 看得到物体的拍 | 动作被截断 | 视觉测速比 Uno |
|---|---|---|---|---|---|---|
| `continuous_20261127_051619_6863` | 2 | 2 / 45 | 1 | 29% | 4% | −2.1 cm/s |
| `continuous_20261127_051734_7923` | 9 | 8 / 178（1 件没完整看到物体，跳过） | 6 | 24% | 13% | −3.6 cm/s |

- **对齐**：实测关节落后 NERO 指令 90 ms，和之前测的真机响应一致，两份数据时间对得上。
- **能看到物体的时间很短**：在 NERO 的等待位上，腕部相机看不到来料，接近段开始时才第一次完整看到物体。每件只能看到约 6 帧，之后 NERO 下降很快，物体进入近距盲区，后面一直靠记忆外推，直到闭爪（约 1.09 s）。
- **RL 的视觉测速偏低 12～20%**（取最后一个可见帧的估计值和 Uno 对比）。2026-11-27 查明原因：
  - **不是 Uno 不准。** NERO 从固定相机拍到物体到接触要隔 4.5～5.3 s，带速差 30% 就会偏 25 cm，而它确认夹住了 6/8 件。
  - **不是相机延迟补偿。** 补偿值从 0 改到 0.2 s，估计速度只变 0.5 cm/s；相机静止的帧里同样偏低。
  - **是物体只被看到一部分。** DC1 深度图左侧约 84 列是双目的无效带，上方一片被夹爪手指挡住，长期无效的区域约占画面 30%。物体从左侧（上游）进入画面，上游部分一直落在无效带里。感知程序只把“碰到画面边缘 4 px 以内”判为截断，所以把半个物体当成整个物体：量出的长度从 46 mm 一路涨到 138 mm（实物 82 mm），中心只以约一半的速度移动。
  - 按“轮廓碰到长期无效区域就算截断”重算，这两组数据 11 件里，每件最多只剩 2 帧完整看到物体。也就是说，在 NERO 的等待位和轨迹下，**腕部相机基本看不到完整的物体**。
  - 同一套感知也用在 RL 真机部署（step6/7），仿真里也没有这条无效带。所以这不只是示范数据的问题。

**2026-11-27 已修**（详见 `docs/设计说明.md`“只看到一部分的物体”）：
- 真机感知：轮廓碰到大片无效深度或夹爪就不算完整看到；
- 仿真：加上双目无效带，并要求顶面完全露出。

修后重新转换了全部数据：
- 只要一件有 ≥ 3 帧完整画面，测速就和 Uno 对上（17.4 对 17.8、21.2 对 21.5 cm/s）；
- 但在 NERO 现在的等待位和轨迹下，**几乎看不到完整的物体**：62 件里只剩 11 个回合能启动，每回合 1～2 帧，29 cm/s 时一件都没有。原来的 53 个回合都是用“半个物体”的观测拼出来的，已经不再使用：转换不出回合的目录里，旧的 `demos.npz` 也删了。
- 同一天又修了一处（物体顶面中间的反光空洞不再算遮挡，见 `deploy/perception.py`），再转换一次：14 个回合，每回合仍是 1～2 帧。凑够 3 帧的 3 个回合，测速比 Uno 偏 −0.3 cm/s。不到 3 帧的回合测不出速度，汇总里记 NaN，不再记成 0。

要让示范数据可用，得先让腕部相机在 NERO 动之前就能完整看到来料，比如调整 NERO 的等待位，让 DC1 看着更上游的带面。原始录制都在，改好后可以对新录的数据直接转换。

还没做的：
- **奖励。** 仿真里的奖励要用真值抓取，真机上没有。已经逐拍存了物体中心、TCP、夹爪开口，放进 SAC 经验池时再按需要算。
- **用这些数据训练的脚本。** 行为克隆预训练，或者示范数据和仿真数据混合采样，是下一步。
