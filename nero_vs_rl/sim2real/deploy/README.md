# 真机测试流程 · 离线阶段（机械臂不动）

目标：第一次让策略控制真机**之前**，先确认"策略在真机上看到的东西"和仿真里一样。

> 离线阶段验收之后，进入**闭环阶段**（step4 仿真干跑 → step5 第一次运动 → step6 跟随 → step7 抓取），流程见 [闭环阶段.md](闭环阶段.md)。

本阶段全程**只读**机械臂：程序不使能机械臂、不发运动指令、不改 CAN。机械臂由操作者用示教/拖动模式（或厂家上位机）摆姿态。

```text
step1_record   DC1 深度/彩色 + 关节角  →  录制目录（数据盘）
step2_replay   录制 → 感知（找物体、算抓取）→ 记忆/测速 → 观测 → 策略  →  报告 + 视频
```

感知之后的记忆、外推、观测拼装，和训练环境调用的是**同一份代码**（`envs/observation.py`）。真机和仿真唯一的区别是"这一帧看到了哪些抓取"从哪里来：仿真里是真值加噪声，真机上由 `perception.py` 从深度图里检测。

## 流程总览

| 阶段 | 做什么 | 用时 |
|---|---|---|
| A. 出发前 | 仿真干跑，确认程序和磁盘空间 | 5 分钟 |
| B1～B3 | 连线、启动 CAN、检查设备 | 10 分钟 |
| B4 | 摆等待位（`--check-pose` 实时显示偏差） | 5 分钟 |
| B5 | 录制三段 + 测相机延迟一段 | 20 分钟 |
| B6 | 现场快速回放第一段，有问题当场重录 | 5 分钟 |
| B7 | 收尾 | 2 分钟 |
| C. 回来后 | 完整回放三段，把汇总发给我 | 10 分钟 |

下面每条命令都可以直接复制。**所有 python 命令都要在激活了 `.venv` 的终端里、在工程目录下运行**（系统里没有 `python` 命令，只有激活 `.venv` 后才有）。

## B. 实验室

### B1. 上电、连线

1. 机械臂上电，USB-CAN 插到电脑上。
2. DC1 的 USB 线插到电脑上，尽量插 USB3 口；插 USB2 也能用，约 24 帧/秒。
3. 打开传送带电源，先不开动。

### B2. 启动 CAN（操作者执行）

```bash
sudo ip link set dev can0 type can bitrate 1000000 && sudo ip link set dev can0 up
```

### B3. 进环境、检查设备

```bash
cd /home/yunfeiwu/桌面/my_RL && source .venv/bin/activate
```

```bash
python -m nero_vs_rl.sim2real.calibration.step0_check_devices
```

相机和机械臂两部分都要通过（输出说明见标定 README 第 1 节）。只检查一部分时加 `--camera` 或 `--arm`。

### B4. 摆等待位

1. 运行摆位检查。它只读关节，屏幕上实时显示当前 TCP 离仿真初始位姿差多少：
   ```bash
   python -m nero_vs_rl.sim2real.deploy.step1_record --check-pose
   ```
2. 用拖动模式（或厂家上位机）把机械臂摆到相机朝下看带的位置，夹爪张开。v6 起的位置是：TCP 在带中心线往远离机器人一侧约 8 cm、带面上约 28 cm（v5 是中心线正上方 22 cm）。
3. 一边调一边看屏幕，直到显示 `✓ 可以录`：

   | 项 | 要求 |
   |---|---|
   | 每轴偏差 | ≤ 30 mm |
   | 倾斜 | ≤ 5° |
   | 偏航 | ≤ 23° |

   这就是训练时初始位姿的随机范围。程序开头还会打印仿真初始位姿对应的关节角，可以作参考。
4. 松手，确认机械臂静止，按 `Ctrl+C` 退出。

### B5. 录制三段 + 测延迟一段

录制期间机械臂**保持不动**（第 3、4 段除外）。开带后先开始录，再在上游**一个一个**放物体，让它们从相机下面经过，相邻两个之间间隔 ≥ 1 秒。v6 起物体可以放在带宽内任何位置（训练时横向铺满整条带）；v5 只训练过带中间 ±7 cm。

**第 1 段（最重要）：** 同一种物体，放 5～10 次。

```bash
python -m nero_vs_rl.sim2real.deploy.step1_record --seconds 60 --note "第1段：纸盒 长8 宽5 高4 cm，带速约4cm/s，机械臂不动"
```

**第 2 段：** 换物体（至少一个圆柱），带速快慢各来几次（如果带速可调）。

```bash
python -m nero_vs_rl.sim2real.deploy.step1_record --seconds 90 --note "第2段：圆柱 直径5 高6 cm + 长方体 ...，带速 ..."
```

**第 3 段（可选）：** 用拖动模式手动跟着物体往下走，模拟靠近抓取，检查盲区和记忆外推。

```bash
python -m nero_vs_rl.sim2real.deploy.step1_record --seconds 60 --note "第3段：拖动跟随，纸盒 ..."
```

**第 4 段（测相机延迟）：** 带**停住**，在相机下方的带上放一个物体不动；用拖动模式让机械臂在物体上方**匀速来回扫** 30 秒。扫的时候物体要一直在画面里，速度大约每秒 10～30 cm，不要猛甩。

```bash
python -m nero_vs_rl.sim2real.deploy.step1_record --seconds 30 --note "第4段：测延迟，带停，长方体静止，拖动来回扫"
```

```bash
python -m nero_vs_rl.sim2real.deploy.step3_measure_latency --latest --apply
```

- 程序会试 −0.1～0.3 s 的各个延迟，找出让静止物体在基座系里"最不晃"的那个，写进 `dc1_site.yaml` 的 `camera.latency_s`。之后的回放和部署取关节角时会自动按它补偿。
- 有警告（机械臂没怎么动、最优值落在边界上）时不会写入，重录这一段。

- 录制时屏幕上会显示深度预览，按 `q` 可提前结束。
- 通过 SSH 远程运行、没有显示器时，加 `--no-preview`。
- 每段结束都会打印录制目录和一条可以直接复制的回放命令。
- `--note` 里写清物体尺寸和带速，回放时要拿它和检测结果对照。

### B6. 现场快速回放第 1 段

趁还在实验室，先检查第 1 段，有问题可以当场重录。录完第 1 段**紧接着**运行：

```bash
python -m nero_vs_rl.sim2real.deploy.step2_replay --latest --video
```

`--latest` 就是最新录的那一段。如果已经录了后面几段，step1 每段结束时都会打印一条可以直接复制的回放命令（带上了那一段的真实目录）；也可以先列出所有录制，再把目录名复制进 `--record`：

```bash
ls -d /home/yunfeiwu/adddisk1/MY_RL_test/real/*_record
```

> 命令里不要出现 `<...>` 这样的尖括号：bash 会把 `<` 当成"从文件读入"，报"没有那个文件或目录"。

**当场必须看的三项：**

| 项 | 合格 | 不合格怎么办 |
|---|---|---|
| 每个物体的尺寸 | 和 `--note` 里的实物尺寸差 < 5 mm | 物体换成哑光的；仍不行，把汇总发给我 |
| 带面 z | −0.107～−0.117（step5 当时测得 −0.112） | 差 5 mm 以上，说明相机可能被碰动了，要重做标定 step1～step3 |
| 估计速度方向 | 偏离 −Y < 15° | 同上，检查相机是否松动 |

打开视频（路径见输出最后一行）看一眼：白框应当框住物体，绿点在物体上。

- 关带。
- 机械臂由操作者按平常方式放回安全位置。
- 需要的话，由操作者关闭 CAN：`sudo ip link set dev can0 down`。

### 完整验收

| 项 | 合格 | 不合格时先查 |
|---|---|---|
| 物体尺寸 | 与实物差 < 5 mm，逐帧标准差 < 5 mm | 物体反光或太黑；手眼标定 |
| 物体类型 | 长方体/圆柱判对（多数票） | 物体形状离长方体/圆柱太远 |
| 带面 z（物体正下方） | 和 step5 测得的 −0.112 差 < 5 mm（程序会自动检查） | 相机被碰动 → 重标定 |
| 估计速度 | 方向偏离 −Y < 15°，速率 ≈ 实际带速 | 手眼标定；相机松动 |
| 偏离中心线 | v6：在带宽内即可；v5：±7 cm 以内 | 放物体的位置 |
| 起始 TCP 离仿真初始位姿 | < 50 mm | B4 没摆好 |
| 观测全部在训练空间内 | 是 | 程序问题，告诉我 |
| 策略朝向抓取的帧 | > 60%（仿真干跑约 86%） | 先看上面几项 |

仿真干跑的参考值（`--sim` 录的，有真值）：

- 位置误差 0.9 mm，尺寸误差 0.1 mm，类型正确率 100%，速度方向偏差 0°；
- 策略朝向抓取 86%，远处要闭合夹爪 17%。

真机深度有噪声，误差会大一些。

## 常见问题

| 现象 | 处理 |
|---|---|
| 没有 `python` 命令，或 `No module named nero_vs_rl` | 没进工程目录或没激活环境：`cd /home/yunfeiwu/桌面/my_RL && source .venv/bin/activate` |
| `bash: ...: 没有那个文件或目录`（命令里有 `<...>`） | 尖括号是占位写法，要换成真实目录；用 `--latest` / `--all` 就不用填目录 |
| `can0 没有启动` | 执行 B2 |
| `连上 CAN 但 3 s 内没收到关节反馈` | 检查机械臂电源；固件版本不是 v121 时加 `--firmware` 和实际版本号 |
| `DC1 取帧超时` / 找不到相机 | 拔插相机 USB，再跑 `step0_check_devices --camera` |
| 预览窗口打不开（SSH） | 加 `--no-preview` |
| 检出率很低 | 看视频：物体是否太矮（< 1.2 cm 不算物体）、反光、超出带宽，或者一直在画面边缘 |
| 尺寸逐帧波动大 | 物体表面反光；换哑光物体 |
| 一个物体被拆成两个编号 | 中途有 ≥ 10 帧没检出（被遮挡或出画面），不影响结果 |
| 拖动段（第 3 段）尺寸、类型、带面高度乱跳 | 拖得太快或相机延迟没补偿；先做第 4 段测延迟 |
| 摆位检查一直显示 `✗` | 按屏幕上 x / y / z 的正负号往反方向挪；倾斜大说明相机没朝正下方 |

## 2026-11-22 第一次真机录制结果

三段录制（`/home/yunfeiwu/adddisk1/MY_RL_test/real/20261122_0410*`、`0411*`、`0413*`），模型 `sac_dc1_v2_ft`。

| 项 | 结果 |
|---|---|
| 长方体（尺子量：宽 46 × 长 82 × 高 58 mm，含 20 mm 圆凸台） | 检测 46.5 × 82.8 × 55.7 mm，3 次全部判为长方体 |
| 圆柱（尺子量：直径 38 × 高 57 mm） | 检测 40.1 × 55.0 mm，约 75% 帧判为圆柱（多数票正确） |
| 带面高度（物体正下方） | −0.116 m，和 step5 测得的 −0.112 差 4 mm：相机没被碰动 |
| 带速 / 方向 | 3.6、9.6、13.3 cm/s 三档（第 2 段调过）；方向偏离 −Y 约 4°，和 step5 测的带方向一致 |
| 起始 TCP 离仿真初始位姿 | 23～37 mm（合格） |
| 观测 | 全部在训练空间内 |
| 策略 | 看得到物体的帧里 100% 朝向抓取；离物体 >10 cm 时 21～37% 的帧要闭合夹爪（仿真 17%） |
| 相机延迟 | 第 3 段粗估约 0.07 s（只有 10 Hz 关节，不够准）；第 4 段正式测得 0.08 s，见下一节 |

尺子量的实物尺寸本身有 1～2 mm 误差，所以上面的差值只说明"在验收线 5 mm 以内"；更可靠的是自洽性：同一物体多次经过，检测尺寸相差 < 1 mm。

发现并已改正：长方体顶上的圆凸台一开始被当成直径 3～4 cm 的圆柱（感知只看最高一层），手指按它去抓会插到底座上；现在用物体上半部分的整体轮廓量尺寸。

## 2026-11-22 相机延迟测量（第 4 段）

两次录制（`20261122_220305_record`、`20261122_220405_record`），带停、长方体静止、拖动机械臂来回扫 30 秒，关节 100 Hz。

| 录制 | TCP 速度（90 分位） | 最优延迟 | 残差（最优 / 不补偿） |
|---|---|---|---|
| 22:03 | 9.0 cm/s | 0.06 s | 2.4 / 4.3 mm |
| 22:04 | 16.6 cm/s | 0.08 s | 8.0 / 11.4 mm |

两次一致，`--apply` 写入的是 0.08 s（22:04 那次，扫得更快、对延迟更敏感）。补偿前后对比（用 v4 模型回放）：

| 项 | 不补偿 | 补偿 0.08 s |
|---|---|---|
| 第 3 段（拖动跟随）各物体下方带面高度 | −0.123～−0.087 m，4 个物体偏差 > 20 mm | −0.121～−0.112 m，全部在 ±9 mm 内 |
| 第 3 段运动方向偏离 −Y（排除 5 帧的误检） | 5 个物体偏 20°～152° | 只剩 2 个只有 7～8 帧的物体偏 25°、39° |
| 第 4 段静止物体逐帧尺寸标准差 | 4.3 / 14 mm | 3.0 / 9 mm |

第 1、2 段机械臂不动，延迟不影响结果。

**v4 模型（带速 4～50 cm/s、8 s 限时）回放：**
- 看得到物体的帧里 74～93% 朝向抓取（v2_ft 是 100%）；离得远就要闭合夹爪 0～1%（v2_ft 21～37%）。
- 仿真里同样让机械臂不动、用同一指标查询，朝向比例是 86～88%。所以大部分差异来自 v4 自己的动作风格，真机只比仿真低 5～12 个百分点。

## 已知的仿真/真机差异（闭环前要处理）

1. ~~**带速超出训练范围。**~~ 已解决：v4 按 4～50 cm/s 训练，第 2 段的 9.6、13.3 cm/s 都在范围内。

2. **物体刚进画面时，真机比仿真晚看到。**
   - 仿真里，抓取点一进画面就给出真值抓取；
   - 真机上，顶面没完全进画面就量不准尺寸，这一帧不用。
   - 仿真干跑里，这样的帧约占仿真可见帧的一半，多数在物体刚进画面和快离开画面时。
3. ~~**策略没看到目标时会"闭合夹爪 + 后退"。**~~ 已处理：闭环回合状态机（`runtime/episode.py`）等**第一次完整检出物体**之后才启动策略。
   - 原因：训练时"完全没有抓取信息"几乎只发生在已经抓住物体、物体进了盲区的时候，所以策略把它学成了"抬起"。
   - 另一种办法（还没做）：把仿真的可见性规则改成和真机一样（顶面完整在画面内才算看到）再微调。
