# 真机测试流程 · 闭环阶段（机械臂会动）

前提：离线阶段（[README.md](README.md) 的 step1～3）已经验收：尺寸、带面、速度方向、相机延迟都正常。

本阶段的程序会让机械臂运动，**只在操作者明确要运行时才运行**。每个会动的程序都分两步：

1. 不加 `--execute`：只读预演。整条链路照跑，CAN 发送被禁掉，机械臂不动。
2. 加 `--execute`：先过开机检查，再由操作者在终端输入 `yes`，才开始动。

程序不使能机械臂、不复位、不改 CAN；没使能就报错退出。

## 1. 架构：一拍（10 Hz）里发生什么

```text
DC1 取帧线程（~24 帧/秒，只留最新一帧）           NERO 反馈（100 Hz 关节历史、驱动状态、夹爪）
        │                                                │
        ▼                                                ▼
┌──────────────────────── 10 Hz 控制循环  runtime/episode.py ────────────────────────┐
│ ① 读：最新深度帧、当前关节、夹爪开口                                                │
│ ② 查：驱动故障/未使能/通信中断 → 急停；跟随误差、相机断帧、发送线程停 → 原地停      │
│ ③ 感知：帧曝光时刻的关节（减相机延迟）→ 相机位姿 → perception.py 检出物体 → 抓取     │
│         → envs/observation.py 记忆/测速（和训练同一份代码）                         │
│ ④ 状态机：WAIT 等第一次完整检出 → SERVO：观测 → SAC → 档位处理 → 同一份 IK 控制器     │
│           → safety.py ①查步长 ②修正（拉回工作空间、指尖抬高、软限位）③查位姿/碰撞    │
│           → 抓住并抬高 6 cm → HOLD 停住                                              │
└───────────────────────────────────────┬────────────────────────────────────────────┘
                                        │ 关节目标（10 Hz）
                    runtime/streamer.py：100 Hz 线性插值，每点 ≤ 限速 × 10 ms
                                        │
                    hardware/nero_control.py：move_js（唯一会发运动指令的类）
```

### 代码分层

真机和仿真干跑共用中间两层，只有最底下的设备不同：

| 层 | 文件 | 真机 | 仿真干跑 |
|---|---|---|---|
| 现场流程 | `step5～7`、`lab.py`（开设备、开机检查、确认、预览、回合间菜单） | ✓ | `step4`、`step5 --sim` |
| 执行层 | `runtime/`：`episode.py` 回合状态机、`safety.py` 安全、`streamer.py` 100 Hz 发送、`session.py` 组装、`run_log.py` 日志 | 同一份 | 同一份 |
| 感知/观测 | `perception.py`、`../../envs/observation.py`、`common.py` 运动学孪生 | 同一份 | 同一份 |
| 设备 | `../hardware/nero_control.py` + `dc1_camera.py` | NERO + DC1 | `../hardware/sim_workcell.py`（MuJoCo 虚拟实验室） |

设备层要提供哪些方法，写在 `runtime/devices.py`（`ArmDevice` / `CameraDevice` / `Clock`）。

仿真的时钟是虚拟的：程序睡到某时刻时推进物理。所以干跑是确定性的，而且比实时快；开图形界面时按实时播放。

## 2. 安全设计

### 会让机械臂停下的情况

| 情况 | 谁发现 | 机械臂怎样 |
|---|---|---|
| 驱动报错、碰撞报警、堵转、未使能、CAN 通信中断、反馈超过 0.2 s 没更新 | `nero_control.faults()`，每拍查 | **急停**（SDK 阻尼停止） |
| 100 Hz 发送出错 | `streamer.py` | **急停** |
| 修正后的目标仍不安全：碰带面/护栏/底座、关节越软限位、TCP 偏出工作空间 1 cm 以上 | `safety.check_pose` | 原地停 |
| 控制器给出的目标单拍关节变化超过限速 | `safety.check_step` | 原地停 |
| 实测关节跟不上指令（> 0.15 + 0.4 × 速度比例 rad） | `safety.check_motion` | 原地停 |
| 相机 0.5 s 没有新帧（抓起后停住阶段不查） | `safety.check_camera` | 原地停 |
| 操作者在预览窗口按空格 / `q`，或在终端按 Ctrl+C | `lab.Preview` / `episode.run` | 原地停 |
| 程序异常 | `episode.run` | 原地停，然后报错退出 |
| 程序退出 | — | 停止发送，机械臂保持最后一个位置目标；不急停、不断使能 |
| **任何时候** | **操作者** | **拍急停** |

"原地停"的做法是：发送器把目标换成实测关节，继续以 100 Hz 发送这个位置。

### 自动修正（不停，策略照常跑）

每个目标在 `safety.project` 里依次修正：

1. **TCP 拉回工作空间。** 控制器已经把期望位置截在工作空间里，但 IK 同时要满足姿态，实际解可能偏出 1～3 cm。修正前，仿真干跑 100 回合里有 17 回合因此被停。
2. **指尖抬高。** 夹爪（指尖、夹爪座）的网格最低点必须高于"安全带面 + 指尖下限"（下表，抓取档 8 mm），不够就把 TCP 竖直抬高，再解一次 IK。
   - 为什么不能只限 TCP 高度：夹爪张开、倾斜 15° 时，外侧指尖比 TCP 低 24 mm。
   - 训练里策略常把指尖顶在带面上（仿真里带面把手指挡住，不扣分），真机不能这样。
   - 全速抓取档的干跑里，87% 的回合触发过这个修正，成功率只比训练档低 3 个百分点。
   - 夹爪落在护栏正上方的部分，还要高于"护栏顶 + 指尖下限"（2026-11-24 起，见第 4 节第 7 条）。
3. **关节截到软限位**（硬限位往里 0.03 rad）。策略抬起时常把 J4 弯到 2.15～2.18（上限 2.18）。

还有三条固定的安全几何和规则：

- **安全带面。** 配置值是 −0.12（独立实测）；标定 step5 用腕部相机测得 −0.112。取更高的那个，宁可少下 8 mm。
- **抓起后停住。** 抓住并抬高 6 cm 就停在原地，夹爪保持闭合。仿真里 v5 抬起后会把物体快速搬到工作空间角上，真机不需要这一段。
- **夹爪开口按张得更开的算。** 检查指尖高度时，取实测开口和指令开口里更大的那个（倾斜时指尖更低）。

### 三个档位（`runtime/safety.py` 的 `PROFILES`）

| 档位 | 用在 | 速度 | 夹爪 | TCP 下限（带面上） | 指尖下限 | 跟随误差阈值 |
|---|---|---|---|---|---|---|
| `sim` | step4 默认（和训练完全一样） | ×1.0 | 可闭合 | 0.8 cm | 不管 | 0.55 rad |
| `follow` | step5、step6 | ×0.3 | 锁定全开 | 10 cm | 3 mm | 0.27 rad |
| `grasp` | step7 | ×1.0 | 可闭合 | 0.8 cm | 8 mm | 0.55 rad |

抓取档的指尖下限 2026-11-24 从 3 mm 提到 8 mm：step5 测到关节在重力方向有 2～5 mm 稳态下沉，3 mm 会让指尖蹭带面。仿真代价（`step4 --profile grasp --lab-belt`，100 回合）：总成功率 62% → 54%，现场带速 84.6% → 76.9%。step4 / step6 / step7 都可以用 `--finger-clearance-mm` 临时改。

**抓取不能降速。** 策略按训练速度掐好了"一边下降一边闭合"的时机，降速后手还没到物体就闭合了，夹空后再重试，直到超时。仿真干跑 100 回合的结果：

- 全速：76%；
- ×0.5：只有 36%，带速 < 8 cm/s 时也只有 54%。

所以只有不抓的跟随档降速。抓取档起步的安全靠：静止物体 / 慢带、上面这些修正和检查、驱动器自带的碰撞报警、操作者拍急停。

### B3. 策略跟随，不抓（`follow` 档）

1. 只读预演：开带、放物体。机械臂不动，预览窗口里看检出框和抓取点，终端里看每回合结果。
   ```bash
   python -m nero_vs_rl.sim2real.deploy.step6_follow
   ```
2. 执行：速度 ×0.3，夹爪锁定全开，TCP 不低于带面上 10 cm。
   ```bash
   python -m nero_vs_rl.sim2real.deploy.step6_follow --execute --episodes 3
   ```

每回合的过程：
1. 终端提示后，在上游放一个物体，按回车；
2. 机械臂原地等，物体第一次完整进入画面（预览出现白框）后策略开始动，跟着物体走 12 s（2026-11-24 前是 8 s）；
3. 停住，终端出菜单：回车 = 张开夹爪并回起点。

合格：
- 机械臂朝物体方向移动、跟着带走；
- 不往下扎（TCP 有 10 cm 下限）；
- 结束原因是 `timeout`（12 s 到了），没有安全停止；
- 回起点正常。

**2026-11-24 第一次真机跟随**（`20261124_031143_closed_loop_follow`，v5，3 回合长方体，带速约 9.5 cm/s）：

| 项 | 结果 |
|---|---|
| 结束原因 | 3 回合都是 `timeout`，没有安全停止，没有触发修正；回起点正常 |
| 靠近物体 | 检出后约 1.5 s 到物体正上方，水平距离最小 2.5～3.3 cm |
| 高度下限 | TCP 最低在安全带面上 9.7～9.9 cm（下限 10 cm；差的 1～3 mm 是 step5 测到的关节稳态下沉） |
| 跟随误差 | 最大 0.094～0.107 rad（阈值 0.27） |
| 每拍计算 | 中位 27 ms，最大 51 ms（10 Hz 一拍 100 ms） |
| 物体底面 z | −0.111～−0.115（中心减半高），和 11-22 的 −0.116 一致：相机没被碰动 |

过了物体之后（约 2 s 后），策略发出闭合指令（被跟随档锁住），然后抬高，并走到工作空间角上 (−0.18, 0.45, 0.28) 停住，3 回合都一样。这是 v5 在训练里抓起后的固定动作：跟随档有 10 cm 下限，手到不了物体，物体从下方进入盲区后不再有抓取信息，策略就当成“已经抓住”。抓取档里，抓住并抬高 6 cm 后程序会停住，不会走这一段。

## 4. 已知限制 / 待现场核对

1. **夹爪宽度换算没核对。** 程序按"真机宽度读数 = 2 × 仿真单指行程"对应。仿真的指垫间距还要再加 8 mm，哪一个对应真机读数，B2 用尺量来定。
2. **跟随误差阈值按仿真定的。** 仿真位置环滞后约 0.2 s。真机滞后由 B2 测；如果小很多，阈值可以收紧，碰撞检测会更灵敏。全速时，"被挡住"和正常滞后分不太开，这时碰撞主要靠驱动器自己的碰撞报警。
3. **物体一直贴着画面边缘走，就不会启动。** 真机感知要求物体顶面完整在画面里，截断的帧尺寸量不准。
   - v5 训练时只要看到一部分抓取点就算看到，用 v5 时约 5% 的干跑回合等不到物体。
   - v6 训练用了同一条规则（`visible_rule: full_top`），起始位姿也能看到整条带，干跑里没有再出现。
   - 用 v5 时，现场把物体放在带中间可以避免。
4. **DC1 外壳不在碰撞检查里。** 模型里的相机外壳是占位位置，已关掉碰撞。标定后的相机在 TCP 上方约 10.6 cm、指尖后方，倾斜时不会先于指尖碰到带面或护栏。
5. **相机延迟只补偿在感知上。** 用帧曝光时刻的关节算相机位姿。策略观测里的 TCP 位姿用当前关节，这和训练一致。
6. **抓起后的放置不是策略做的。** 抓起停住后，由操作者在菜单里张开夹爪、回起点；还没有"搬到料框"这一段。
7. **护栏：指令目标领先实际机械臂。** 安全层用指令目标位姿查碰撞，这个目标比实际机械臂领先约 0.2 s（仿真位置环的滞后）；训练里只罚实际接触。
   - v6 在训练环境里 100 回合实际碰护栏 0 次。闭环干跑里，张着夹爪下降时外侧指尖的目标会伸进护栏，原来直接停，100 回合停了 20 次。
   - 2026-11-24 起，`safety.project` 先把夹爪在护栏正上方的部分抬到"护栏顶 + 3 mm"以上（和避开带面同一个函数），修正后 v6 停 3～4 次/100 回合。
   - 护栏高度按 1.5 cm（11-22 用户说明）。用户 11-24 说真机护栏"很矮、约等于没有"，那样这条修正几乎不起作用。
